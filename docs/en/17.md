# Day 17 — Design a useful CI pipeline

[All days](README.md) · [Animated classroom](../../academy/index.html#day=17)

## The idea

Continuous integration verifies changes automatically. Our stable checks run on push and pull request: three Python versions and a real Docker build/smoke test. Course content and links are checked too. A passing badge only covers configured behavior and can still miss a requirement nobody encoded.

## A familiar example

A repeatable inspection station checks each parcel using the same rules.

## Walk through it

### 1. Trigger

An event such as a PR starts a workflow for a particular commit.

### 2. Runner

A fresh runner checks out that code and prepares its tools.

### 3. Verify

Tests and container checks must fail on bad behavior.

### 4. Report

The result is attached to the commit so the merge gate can evaluate it.
