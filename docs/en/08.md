# Day 8 — How an HTTP request travels

[All days](README.md) · [Animated classroom](../../academy/index.html#day=8)

## The idea

A browser request involves name lookup, a network connection and an application response. localhost refers to the machine making the request. The port selects a listening service. HTTP status describes the application result after a connection exists. Connection refused and HTTP 404 are different layers of failure.

## A familiar example

Reaching the shop door is different from finding the product you asked for.

## Walk through it

### 1. Address

The URL names a destination and optional port.

### 2. Connect

The client tries to connect to a process listening at that address.

### 3. Request

The client sends a method and path such as GET /health.

### 4. Respond

The server returns status, headers and a body. Inspect all three when debugging.

## Try it yourself

Run from the repository root. Read comments and prerequisites first.

```bash
python app.py
# In a second terminal with curl:
curl -i http://localhost:8000/health
```

## Expected evidence

The response is HTTP 200 with JSON content type and status ok. The server logs the request.

## Break, diagnose, recover

Call port 8001 while the app listens on 8000, then call /missing on 8000. Explain refused connection versus 404.
