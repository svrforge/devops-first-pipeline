# Day 27 — Secrets, least privilege and trust

[All days](README.md) · [Animated classroom](../../academy/index.html#day=27)

## The idea

Grant the minimum access needed, keep secrets outside source and do not confuse deleting a secret from a file with revoking it. A real exposed credential must be revoked or rotated. CI should avoid unnecessary write permissions and should not run untrusted changes with privileged secrets.

## A familiar example

Removing a copied key from a photo does not change the lock it opens.

## Walk through it

### 1. Inventory

Identify where credentials could enter a project: env files, logs, state and config.

### 2. Exclude

Inspect ignore files, but remember they do not remove already-tracked files.

### 3. Limit

Read the CI permissions and container runtime identity.

### 4. Respond

Document revocation/rotation and investigation for a hypothetical exposure.
