# Day 20 — Release versions and rollback thinking

[All days](README.md) · [Animated classroom](../../academy/index.html#day=20)

## The idea

A release needs traceability from source commit to built artifact to running version. Rebuilding the same mutable tag is weaker evidence than recording an immutable digest. Rollback should be a deliberate return to a known version followed by behavior verification. Our sample version variable demonstrates identification, not a production release system.

## A familiar example

A parcel label should identify what is inside, not just say latest.

## Walk through it

### 1. Identify

Run the app with an explicit APP_VERSION in your local shell.

### 2. Record

Associate that value with the source commit and build evidence.

### 3. Compare

Call the home endpoint to verify which version is actually responding.

### 4. Recover

Return to the known configuration and verify again, rather than assuming a restart restored it.
