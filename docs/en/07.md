# Day 7 — Pull requests and protected main

[All days](README.md) · [Animated classroom](../../academy/index.html#day=7)

## The idea

A branch is a separate line of work. A pull request proposes bringing that work into another branch and makes checks and discussion visible. Protection on main requires the configured checks and an up-to-date branch. It prevents known failing changes from merging; it cannot prove every possible behavior is correct.

## A familiar example

A quality gate should check the actual parcel before it enters the delivery route.

## Walk through it

### 1. Prepare

Visitors should fork and clone their own copy before pushing.

### 2. Push

Push a feature branch to a repository where you have permission.

### 3. Review

Open a PR and read the diff, not only the title. Identify the tested commit SHA.

### 4. Merge

Wait for all required checks and resolve conversations. Do not bypass the gate.

## Expected evidence

A PR shows the intended diff and check results for its latest commit. Forks need their own protection settings.

## Break, diagnose, recover

Push a deliberate failing test on a disposable branch, observe the red check, fix it, and verify the newer commit passes.
