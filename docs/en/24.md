# Day 24 — State, drift and repeatability

[All days](README.md) · [Animated classroom](../../academy/index.html#day=24)

## The idea

State links configuration to managed objects. A second plan after a successful unchanged apply should show no changes. Real state can contain sensitive data and must not be committed. Drift is a difference between expected managed state and external reality; our local data lab illustrates state transitions, not a full cloud drift experiment.

## A familiar example

An inventory record must be protected and kept aligned with the real warehouse.

## Walk through it

### 1. Apply

Complete the local lab apply interactively.

### 2. Repeat

Run plan again with unchanged inputs and inspect the no-change result.

### 3. Change

Plan a new replica input and explain the difference.

### 4. Clean

Destroy only the local lab resource when finished; keep state out of Git.
