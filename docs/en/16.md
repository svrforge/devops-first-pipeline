# Day 16 — Compose and runtime hardening

[All days](README.md) · [Animated classroom](../../academy/index.html#day=16)

## The idea

Compose describes local service configuration. It is useful for repeatable startup without remembering a long docker run command. This lab limits exposure to loopback, drops capabilities and uses a read-only filesystem. Those controls reduce privileges but do not replace secure application design.

## A familiar example

A repeatable setup checklist is better than remembering every switch by hand.

## Walk through it

### 1. Validate

docker compose config checks the effective configuration.

### 2. Restrict

The mapping binds to 127.0.0.1 so the lab is not intentionally exposed on the LAN.

### 3. Reduce

Read-only filesystem and dropped capabilities limit unneeded runtime powers.

### 4. Observe

Confirm the app still works under these restrictions instead of assuming hardening is harmless.

## Try it yourself

Run from the repository root. Read comments and prerequisites first.

```bash
docker compose config -q
docker compose up -d
docker compose ps
```

## Expected evidence

The configuration validates and /health works with the runtime restrictions enabled.

## Break, diagnose, recover
