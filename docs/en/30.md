# Day 30 — Explain your system and plan the next step

[All days](README.md) · [Animated classroom](../../academy/index.html#day=30)

## The idea

Competence grows through repetition and feedback. Explain the full route from commit to verification to runtime and recovery, including the parts that remain manual. Review weak areas instead of treating day 30 as a certification. Next steps can deepen one area: Linux operations, deployment strategy, networking or observability.

## A familiar example

Finishing a map does not mean you have travelled every road; it gives you a reliable starting route.

## Walk through it

### 1. Explain

Describe the system to another learner without reading every file.

### 2. Demonstrate

Run the app, tests and relevant lab checks.

### 3. Reflect

Identify one failure you can now diagnose and one uncertainty you still have.

### 4. Continue

Choose a focused extension with acceptance criteria and a feedback source.

## Try it yourself

Run from the repository root. Read comments and prerequisites first.

```bash
python learn.py status
python -m unittest discover -s tests -v
```

## Expected evidence

Prepare a five-minute demo and a README of evidence. Be honest about local-only and untested cloud behavior.

## Break, diagnose, recover

Have a reviewer ask why each tool exists. Remove unnecessary complexity from your explanation and design.
