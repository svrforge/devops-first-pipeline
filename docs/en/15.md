# Day 15 — Running is not the same as healthy

[All days](README.md) · [Animated classroom](../../academy/index.html#day=15)

## The idea

Running means the process has not exited. Healthy means a configured probe has passed. A process can be alive while unable to answer correctly. Probe design should match the purpose: basic liveness is different from readiness to receive traffic.

## A familiar example

A shop light can be on while its payment system is broken.

## Walk through it

### 1. Start

The verification script starts a dedicated disposable container.

### 2. Probe

Docker repeatedly calls the image health command with timeouts.

### 3. Verify

The script waits for health and checks actual JSON plus the non-root UID.

### 4. Clean

Its exit trap removes its own container, even when verification fails.

## Try it yourself

## Expected evidence

The script reports health, response and non-root checks passed; it removes the container afterward.

## Break, diagnose, recover

Change the health-check path to a missing route in a branch. Build a new image, observe unhealthy behavior, restore and rebuild.
