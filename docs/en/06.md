## In simple words

Record one small change with Git. Start with the short explanation below. Read the new-word meaning, follow one part at a time, and try the activity only when the idea makes sense. You do not need to memorize a list of tool names.

Git records snapshots, not just filenames. A commit should explain one coherent change. Inspect your working tree and diff before staging. Staging specific files helps avoid publishing unrelated notes or credentials. A local commit has not automatically reached GitHub.

## Small activity

[Official Git installation guide](https://git-scm.com/downloads/)

```bash
git --version
git clone https://github.com/svrforge/devops-first-pipeline.git
cd devops-first-pipeline
git status
git switch -c learning/day-06
# After editing START-HERE.md:
git diff
git add START-HERE.md
git diff --staged
git commit -m "Clarify local setup instructions"
```

## What you should notice

You can explain which file changed and see it in one local commit. If Git asks for your identity, configure it using the official Git setup guide, then try again. A local commit is not yet uploaded to GitHub.

## Think about this

Edit two files but stage only one. Inspect git diff and git diff --staged to understand the difference.
