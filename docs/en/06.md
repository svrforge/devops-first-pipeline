# Day 6 — Git: record a meaningful change

[All days](README.md) · [Animated classroom](../../academy/index.html#day=6)

## The idea

Git records snapshots, not just filenames. A commit should explain one coherent change. Inspect your working tree and diff before staging. Staging specific files helps avoid publishing unrelated notes or credentials. A local commit has not automatically reached GitHub.

## A familiar example

A saved notebook entry is different from sending that notebook to your team.

## Walk through it

### 1. Inspect

Run git status to see the current branch and changed files.

### 2. Branch

Create a learning branch rather than modifying main directly.

### 3. Change

Make one small documentation correction and inspect git diff.

### 4. Record

Stage that file, commit with a useful message, then inspect the new commit.

## Try it yourself

Run from the repository root. Read comments and prerequisites first.

```bash
git status
git switch -c learning/day-06
git diff
# After editing a documentation file:
git add START-HERE.md
git commit -m "Clarify local setup instructions"
```

## Expected evidence

The commit contains only the intended documentation change. Git needs your name/email configured before the first commit.

## Break, diagnose, recover

Edit two files but stage only one. Inspect git diff and git diff --staged to understand the difference.
