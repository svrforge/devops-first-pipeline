# Day 23 — Terraform: plan before apply

[All days](README.md) · [Animated classroom](../../academy/index.html#day=23)

## The idea

Terraform compares declared configuration and recorded state to propose changes. Plan previews; apply performs. The built-in terraform_data lab creates no cloud compute. That isolates the workflow so you can learn without credentials or bills. Real infrastructure requires separate approvals and controls.

## A familiar example

An architect reviews a change drawing before builders alter the building.

## Walk through it

### 1. Initialize

Prepare the local working directory with terraform init.

### 2. Validate

Check syntax/configuration before planning.

### 3. Plan

Read the proposed resource and output changes.

### 4. Apply

For this local lab, approve interactively only after understanding the plan.

## Try it yourself

Run from the repository root. Read comments and prerequisites first.

```bash
terraform -chdir=labs/terraform init
terraform -chdir=labs/terraform validate
terraform -chdir=labs/terraform plan
```

## Expected evidence

The plan proposes a local terraform_data object; there are no OCI credentials or cloud resources.

## Break, diagnose, recover

Plan with replicas=0 and confirm input validation rejects it. Use replicas=3 to inspect a valid change.

## Check your understanding
