# Day 2 — Set up your learning workspace

[All days](README.md) · [Animated classroom](../../academy/index.html#day=2)

## The idea

Your workspace is the folder containing source, tests and instructions. A terminal is a text interface to programs; it is not a special DevOps server. Start with Git and Python, then add tools only when a lesson needs them. Keep this learning work separate from workplace credentials and clusters.

## A familiar example

Think of a workshop: you need a clean bench and a few tools before buying an entire factory.

## Walk through it

### 1. Locate

Open a terminal and enter the repository root. Relative paths are interpreted from this working directory.

### 2. Inspect

Check Git and Python versions. If python is missing, Windows may use py and macOS/Linux may use python3.

### 3. Diagnose

Run the doctor command. A missing optional tool is information, not a reason to abandon the first lessons.

### 4. Verify

Run the tests from the root so Python can import app.py. Save the output as your first evidence.

## Try it yourself

Run from the repository root. Read comments and prerequisites first.

```bash
git --version
python --version
python learn.py doctor
python -m unittest discover -s tests -v
```

## Expected evidence

Git and Python are available; tests finish with OK. Optional Docker, kind and Terraform may be missing today.

## Break, diagnose, recover

Run the test command from another folder and observe the path/import problem. Return to the repository root and run again.
