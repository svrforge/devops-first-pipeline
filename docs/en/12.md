# Day 12 — Red, green, refactor

[All days](README.md) · [Animated classroom](../../academy/index.html#day=12)

## The idea

First define expected behavior with a failing test; implement the smallest correct change; improve structure without changing the contract. This cycle creates feedback while work is still small. Updating expected values merely to silence an unintended regression defeats the purpose.

## A familiar example

Measure the part, fix the part, then improve the workshop without changing its size.

## Walk through it

### 1. Red

Describe /ready in a new HTTP test; run it and confirm the route is missing.

### 2. Green

Implement /ready with the agreed status and body.

### 3. Refactor

Remove duplication only after correctness is established.

### 4. Verify

Run the entire suite, not only the new test, to catch collateral changes.

## Try it yourself

## Expected evidence

Your new /ready test initially fails and later passes; existing home/health/404 tests remain correct.

## Break, diagnose, recover

Make the new route accidentally replace /health. The full suite should detect the regression; restore both contracts.
