# Day 1 — The journey from code to a running service

[All days](README.md) · [Animated classroom](../../academy/index.html#day=1)

## The idea

You do not need to learn ten tools today. You need to understand one journey: someone changes code, the team checks it, a build packages it, and a running service handles a request. DevOps makes that journey repeatable and observable. It also makes recovery part of delivery, rather than an afterthought.

## A familiar example

Imagine a small shop taking online orders. A developer fixes the order page, but customers still see the old version. The problem is no longer just coding: the team must test, package, release, observe and recover together.

## Walk through it

### 1. Change

A developer edits source code. The edit exists only in a working copy until it is recorded.

### 2. Verify

Automated tests compare actual behavior with the contract. A failure means stop and investigate.

### 3. Package

A build produces something repeatable, such as a container image. The same input should be traceable to the output.

### 4. Operate

Run the service, observe its responses and keep a known recovery path. Shipping is not the end of ownership.

## Try it yourself

Run from the repository root. Read comments and prerequisites first.

```bash

```
