# Day 13 — Build your first container image

[All days](README.md) · [Animated classroom](../../academy/index.html#day=13)

## The idea

An image contains the application and its runtime filesystem. Dockerfile instructions describe how to build it. An image is not a running server until a container starts. Build context matters: only send the files needed, and exclude local state or credentials.

## A familiar example

A packed lunchbox is ready to travel, but nobody has opened it yet.

## Walk through it

### 1. Base

FROM chooses a runtime image. Upstream changes can affect future builds.

### 2. Copy

COPY adds application source from the build context.

### 3. Identity

USER sets the runtime identity; this project uses UID 10001.

### 4. Command

CMD supplies the default startup command when a container is created.

## Try it yourself

Run from the repository root. Read comments and prerequisites first.

```bash
docker build -t devops-first-pipeline:local .
docker image inspect devops-first-pipeline:local
```

## Expected evidence

The image is built and inspect shows the configured command and non-root user. Docker must be running first.

## Break, diagnose, recover

Read .dockerignore and explain why .git, .env and local state should not enter image context.
