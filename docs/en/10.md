# 10 · Terraform and desired state

[Course index](README.md) · [English](../en/10.md) · [தமிழ்](../ta/10.md)

## Understand

Infrastructure as code describes desired resources and records their relationship in state. Plan previews changes; apply executes them. Our terraform_data lab uses the built-in provider and creates no cloud resources. State still deserves care: never commit it, because real infrastructure state may contain sensitive values. A plan is a proposal, not permission to apply in production.

## Try it

Run from the repository root. Commands are examples to run yourself; the learning CLI never executes them.

```bash
terraform -chdir=labs/terraform init
terraform -chdir=labs/terraform plan
terraform -chdir=labs/terraform apply
```

## Verify

Review the plan interactively. Output shows the service name and replicas. A second plan says no changes.

## Break, diagnose, recover

Change replicas from 2 to 3 via -var="replicas=3" in plan; explain the proposed input update before applying.
