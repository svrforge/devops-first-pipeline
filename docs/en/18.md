## In simple words

Find the cause of one failed check and choose a suitable fix. Start with the short explanation below. Read the new-word meaning, follow one part at a time, and try the activity only when the idea makes sense. You do not need to memorize a list of tool names.

Start at the first meaningful failed step, not the final red summary. Separate source failures from tool setup, network or runner failures. Reproduce the exact command where possible. Rerunning unchanged code is appropriate for a demonstrated transient failure; it is not a substitute for diagnosis.

## Part 1: Locate

Open the failed run and identify the first failing job/step.

**New word — Build log:** The recorded output from automated work.

**Example:** Repeatedly pressing a broken doorbell is not the same as tracing its wiring.

## Part 2: Classify

Ask whether setup, compilation, test assertions or container startup failed.

**New word — Transient failure:** A temporary problem, such as an unavailable network service.

**Example:** Ask whether setup, compilation, test assertions or container startup failed.

## Part 3: Reproduce

Run that command locally with the same inputs.

**New word — Regression:** A change that breaks behavior that used to work.

**Example:** Run that command locally with the same inputs.

## Part 4: Fix
