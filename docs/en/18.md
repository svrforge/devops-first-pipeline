# Day 18 — Read a failed build like an engineer

[All days](README.md) · [Animated classroom](../../academy/index.html#day=18)

## The idea

Start at the first meaningful failed step, not the final red summary. Separate source failures from tool setup, network or runner failures. Reproduce the exact command where possible. Rerunning unchanged code is appropriate for a demonstrated transient failure; it is not a substitute for diagnosis.

## A familiar example

Repeatedly pressing a broken doorbell is not the same as tracing its wiring.

## Walk through it

### 1. Locate

Open the failed run and identify the first failing job/step.

### 2. Classify

Ask whether setup, compilation, test assertions or container startup failed.

### 3. Reproduce

Run that command locally with the same inputs.

### 4. Fix

Make a focused change and verify a new run for the newer commit.
